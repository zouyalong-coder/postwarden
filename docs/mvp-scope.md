# MVP 范围与验收边界

## 必须交付

1. 单个 Rust 服务同时提供管理页面、Admin API、发送 API 和同进程异步 Worker；Vue 页面由服务自身托管，无必需的独立前端服务器。
2. 单一本地管理员：安全初始化、登录、退出和会话保护；管理员与发送 Token 认证严格分离。
3. SMTP Account 增删改查、启停、凭证加密、连接测试和测试邮件；Sender Identity 独立管理，允许一个账号关联多个身份。
4. API Token 创建、一次性明文展示、有效期、启停、撤销、身份授权和轮换所需的新旧 Token 并存。
5. 同步与异步发送接口：收件人、抄送、密送、主题、文本/HTML 正文及附件；强制幂等键；身份权限校验；明确区分 SMTP 接受、失败和结果不确定。
6. 异步状态查询、数据库队列、同进程 Worker、有限且安全的重试、任务到期、进程重启后的保守恢复；同步请求遇暂停返回 `requires_async`。
7. 消息、尝试和生命周期审计；正文及附件加密暂存；待发送最长 7 天、所有终态内容保留 7 天、审计与幂等记录保留 90 天，三项均可配置。
8. 可用的构建期插件接口：插件注册、启停及顺序、提交前/发送前/结果后三类钩子、修改/拒绝/暂停语义、插件状态持久化、常规错误处理与记录。MVP 可用示例插件验证接口，但不要求交付完整模板或审批功能。
9. SQLite 与 MySQL 双数据库适配器、各自迁移和共同的行为测试；单实例部署、Docker 镜像及两种数据库配置示例；可直接配置 HTTPS 证书或接入已有 TLS 网关。

## 暂不实现

- 运行时上传或热安装插件包、WASM 执行器、原生动态库插件。
- 完整模板管理、发送审批、内容检查、回调等具体业务插件；仅提供其所需的核心流程接口和扩展边界。后续版本已增加 `mail-template` 插件及邮件成形、插件管理资源接口。
- 多管理员、角色分级、企业单点登录及外部身份提供方。
- 独立 Worker、Redis/消息中间件、正式多实例高可用部署。
- 从 SQLite 到 MySQL 的自动数据迁移工具，或修改配置后自动搬迁数据。
- 收件、退信接收、投递回执、邮箱管理、SMTP Server。
- 保证邮件“恰好发送一次”或“收件人最终送达”；SMTP 网络中断后可能存在无法消除的结果不确定性。

## 首版验收原则

- 两种数据库均通过同一组账号、授权、发送、队列、到期、审计和保留规则测试；不能只让 MySQL 能连接而缺少完整功能。
- 禁用或撤销 Token、身份、账号后，尚未开始 SMTP 的异步任务不能继续发送；权限被撤销的调用方不能访问管理 API。
- 相同幂等键及相同请求在同步、异步入口内不会产生第二次发送；复用键但更改内容或模式返回冲突。
- 插件的修改、拒绝和暂停结果均能改变实际控制流程；暂停任务在重启后仍可恢复或到期，插件错误不会绕过发送前检查。
- `expired` 的加密内容按终态内容保留期保存，不因到期立即删除；审计和幂等记录按独立期限清理。
- 管理页面、发送 API、Worker、SQLite 模式可由一个服务启动；MySQL 模式只需额外的数据库，不需 Redis、Nginx 静态托管或第二个 PostWarden 进程。
