# PostWarden 系统架构

状态：阶段一整体方案已确认；本文件为阶段二架构说明。

## 定位与边界

PostWarden 是自托管的 SMTP 发送代理和授权中心，不接收邮件，不管理邮箱，也不实现 SMTP Server。调用方仅持有 PostWarden API Token，不接触 SMTP 凭证。首版支持单实例部署；服务包含 HTTP API、管理页面和同进程异步 Worker。

## 技术方案

| 部分 | 方案 |
| --- | --- |
| 后端 | Rust；HTTP 框架采用 Axum，异步运行时采用 Tokio |
| SMTP | 使用成熟的 Rust 邮件库（候选：lettre），封装在发送适配器后；正式选定版本需验证 TLS、认证、附件、超时和错误分类 |
| 管理页面 | Vue 构建为静态资源，由 Rust 服务在同一地址提供；发布构建将资源嵌入可执行文件 |
| 数据库 | SQLite（默认）及 MySQL（MVP 正式支持）；使用 SQLx 和数据库专用迁移 |
| 插件 | 独立 Rust crate，在构建时链接、启动时注册；增加插件需要重新构建 |

单个发布构建同时包含 SQLite 与 MySQL 适配器，运行时通过配置选用其一。修改数据库配置只选择新的数据源，不搬迁旧数据。

## 模块边界

| 模块 | 职责 |
| --- | --- |
| Admin Web | 管理员登录及账号、身份、Token、发送历史和插件配置页面；仅调用 Admin API |
| Admin API | 管理操作、SMTP 连接与测试邮件、审计查询；只接受管理员会话 |
| Authentication & Authorization | 管理员会话、API Token 校验、身份授权与撤销状态检查；发送 Token 不可访问 Admin API |
| SMTP Account Management | SMTP 连接配置、凭证加解密、启停与连接测试 |
| Sender Identity Management | 对外显示名称和邮箱地址；一个身份关联一个 SMTP Account，一个账号可以关联多个身份 |
| Mail Sending Service | 同步与异步入口共享的校验、流程调用、SMTP 发送和结果归类 |
| Message Processing Pipeline | 有序执行插件钩子；保存暂停状态；对修改后的内容重新校验 |
| Queue Worker | 从所选数据库领取异步任务，在同一服务进程中发送、重试及恢复 |
| Audit Logging | 消息生命周期和每次 SMTP 尝试的审计记录；独立于插件结果通知 |
| Storage | 业务存储接口及 SQLite、MySQL 适配器；管理事务、任务领取及迁移 |

存储适配器和控制流程插件是两个不同的扩展机制。存储适配器负责数据库差异；控制流程插件负责邮件处理行为。

## 发件资源与授权

SMTP Account 代表真实发送通道，保存主机、端口、TLS/认证设置及加密凭证。MVP 至少支持用户名/密码认证，以及常见的 STARTTLS 和隐式 TLS；不得通过明文连接发送认证凭证。Sender Identity 代表调用方可选择的发件人。MVP 可为每个账号配置一个身份，但数据结构允许一个账号拥有多个身份。发送请求只引用 Sender Identity ID；调用方不能自行覆盖 `From` 或 SMTP 信封发件地址。SMTP 信封地址由服务端配置确定。

API Token 与 Sender Identity 为多对多授权关系。默认无权限，明确授予后才能使用。接收请求时及异步任务实际发送前均检查 Token、身份和 SMTP Account 状态。已撤销 Token 对尚未发送的队列任务失效。为防止排队期间发件地址或账号关联被悄悄替换，异步消息记录身份版本；这些关键属性变化后，旧任务不使用新配置发送，而以明确原因结束。SMTP 凭证轮换可使用账号的当前有效凭证。

## 发送流程

1. 校验请求格式、大小和 `Idempotency-Key`，认证 Token 并核对 Sender Identity 权限。
2. 执行提交前插件；对修改后的内容重新校验，固定消息内容和发送身份。
3. 同步请求在当前 HTTP 请求中继续处理；异步请求加密保存正文与附件、写入消息和任务记录，返回消息 ID。
4. 发送前再次检查当前 Token、身份和账号状态；按顺序执行发送前插件。插件可以继续、修改、拒绝或暂停。修改后的最终内容持久化一次，重试不重复运行修改钩子。
5. 同步流程若要求暂停，返回 `requires_async` 且不发送；该请求以 `rejected` 记录，已占用的幂等键不再用于异步重提。异步流程将插件标识及恢复状态持久化，等待后续动作或到期。
6. SMTP 适配器执行发送，记录尝试、上游响应和状态。结果产生后调用结果钩子；该钩子的失败不会更改已确定的 SMTP 结果。

同步和异步入口共享业务校验、授权、插件与 SMTP 适配器。同步的 HTTP 超时不等于 SMTP 未接受邮件；如无法确认结果，记录 `outcome_unknown`。`smtp_accepted` 只表示上游 SMTP 接受，不表示收件人最终收到。

### 队列与重试

异步任务使用数据库持久化队列，不依赖 Redis 或独立 Worker。领取任务必须是原子操作，SQLite 和 MySQL 分别实现并测试。MVP 仅支持单个 PostWarden 实例；未来多实例需要进一步验证任务协调、插件状态及配置一致性。

仅当能确认 SMTP **尚未接受**邮件且错误属临时故障时，异步任务才有限次重试。明确的永久错误直接失败；在提交邮件内容后超时、进程在发送过程中中断等无法判断结果的情况转为 `outcome_unknown`，不自动重发。同步接口不启动后台重试。具体次数和退避间隔属于实现参数。

## 插件机制

MVP 提供可实际使用的构建期插件机制：公共插件接口 crate、插件 ID 与版本、启动注册、启停配置、确定的执行顺序、插件专属配置与状态存储，以及以下钩子：

| 阶段 | 典型用途 | 允许的结果 |
| --- | --- | --- |
| 提交前 | 模板渲染、内容规范化、内容检查 | 继续并可修改、拒绝 |
| 发送前 | 审核、策略检查、发送窗口 | 继续并可修改、拒绝、暂停 |
| 结果产生后 | 通知、回调、外部审计 | 观察结果；失败仅记录，不篡改发送结果 |

插件修改收件人、主题或内容后，核心重新进行格式、大小和策略校验；插件不能通过流程返回值绕过 Sender Identity 授权。插件状态使用命名空间存储，避免直接依赖 SQLite/MySQL 方言。未来模板或审批插件可以在构建期注册管理 API，并随 Vue 构建加入管理页面。MVP 实现注册和流程机制，不交付完整模板或审批产品功能。

构建期插件与主服务处于同一进程，属于受信任代码；插件作者和部署者必须信任其代码。常规插件错误可以被处理并记录，但同进程代码不具备沙箱隔离。运行时上传插件包、WASM 执行器及原生动态库装载均不在 MVP。若未来加入运行时插件，继续沿用流程阶段和结果语义，再定义独立的跨进程或 WASM 接口。对尚有暂停任务的插件，禁用或升级须先处理其待办状态，不能直接丢弃恢复所需的代码或数据。

## 安全与审计

- 管理员与发送 API 使用不同凭证。MVP 为单一本地管理员；无默认密码。首次管理员凭证通过本地初始化命令设置。管理员密码用 Argon2id 等适合口令的算法哈希，Web 会话使用安全 Cookie 与 CSRF 防护。
- API Token 使用高熵随机值，仅创建时展示明文；数据库存放用于查验的摘要和非敏感标识。支持有效期、禁用、撤销和通过新旧 Token 短暂并存实现轮换。Token 放在 `Authorization` 头中，不放 URL。
- SMTP 凭证和暂存的邮件正文、附件需要可解密，因此使用应用层认证加密。加密主密钥由部署配置提供，与数据库分开保存并纳入备份方案；敏感值不进入日志或普通 API 响应。
- 管理员会话、Token 和邮件内容均须通过 HTTPS 传输。可给 Rust 服务配置证书直接提供 HTTPS，或使用部署者已有的 TLS 网关；不需要额外 Nginx 托管静态页面。
- 审计记录关联 Token、Sender Identity、收件人、时间、消息状态、发送尝试及经过清理的失败原因。默认不把正文及附件复制到长期审计表。密送地址仅向有权查询该消息的调用方及管理员返回，普通服务日志不输出地址或秘密。

## 部署与配置

发布物为包含 Admin Web 的单个 Rust 服务，另提供 Docker 镜像。SQLite 部署挂载数据库文件目录；MySQL 部署提供连接地址和独立数据库。Docker Compose 可分别示范 SQLite 与 MySQL，不引入必需的前端容器、Redis 或独立 Worker。

配置文件和环境变量负责监听地址、数据库类型与连接、TLS 证书、SMTP 凭证加密密钥、队列并发度及保留时间。秘密不写入示例配置。后续横向扩展以 MySQL 等共享数据库为前提，但不能仅靠切换数据库即宣称支持多实例。
