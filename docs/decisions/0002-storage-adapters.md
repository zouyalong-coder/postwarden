# ADR 0002：SQLite 与 MySQL 双适配器

状态：已确认。

## 决定

MVP 同时正式支持 SQLite 与 MySQL；SQLite 是默认单实例配置。业务模块依赖存储接口，两种数据库有各自的适配实现、迁移及行为测试。配置选择数据库，不自动迁移旧数据。SQLx 用于数据库连接和查询，但不把其运行时通用驱动当作消除 SQL 方言差异的方案。

## 理由

SQLite 让自托管单实例无需额外数据库服务；MySQL 满足已有数据库基础设施的团队需求，也是用户明确要求的 MVP 能力。通过存储接口隔离队列领取、事务及查询差异，后续可加入 PostgreSQL 适配器。

## 主要备选

- 仅 SQLite：实现更轻，但不能满足 MVP 的 MySQL 部署要求，也不适合直接承诺未来多实例。
- 仅 MySQL 或 PostgreSQL：统一数据库实现会减少适配工作，但单实例默认部署必须运行额外数据库。
- 使用一个通用 SQL 实现覆盖所有数据库：简单 CRUD 有时可共用，但迁移、队列领取、锁与事务行为存在差异；不应以编译或连接成功代替两种数据库的行为验证。
- 运行时上传数据库插件：对部署者没有实际收益，还增加二进制兼容与安全负担；内置适配器足够。

## 后果

每项存储相关功能都要在 SQLite 和 MySQL 上验证。切换配置后新服务连接的是另一套数据；跨库迁移工具不属于 MVP。MySQL 的存在不意味着首版已支持多实例，横向扩展还需另行设计和验证。
