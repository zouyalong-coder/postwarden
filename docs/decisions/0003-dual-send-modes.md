# ADR 0003：同步及异步发送并存

状态：已确认。

## 决定

提供同步发送和异步入队两个 HTTP 入口，由调用方选择；两者共享认证授权、内容校验、插件流程、SMTP 适配器及审计。异步任务保存在数据库中，由同进程 Worker 处理并提供状态查询。同步流程遇到需要暂停的插件结果时返回 `requires_async`，不发送邮件。

## 理由

部分调用方需要在一次 HTTP 请求中取得 SMTP 接受结果，另一些调用方需要较快返回并允许审核、延迟或重试。共用核心流程保证安全规则一致。数据库队列与现有双数据库方案配合，不为 MVP 引入 Redis 或独立 Worker。

## 主要备选

- 仅同步：实现简单，但审批、延迟发送和持久化重试会改变原有响应语义。
- 仅异步：流程统一，却不能满足明确需要同步结果的调用方。
- 独立队列服务与 Worker：可用于高负载部署，但增加首版运维组件。
- 网络故障后自动反复重试：SMTP 在提交内容后超时可能已被服务器接受，盲目重发有重复邮件风险；因此对不确定结果记录 `outcome_unknown`。

## 后果

API 明确区分 `202 Accepted`（任务已保存）与 `smtp_accepted`（上游 SMTP 已接受）。二者都不表示收件人最终收到。需要持久化加密的异步内容、状态和尝试记录，并在进程重启时保守恢复。同步和异步均要求幂等键。
