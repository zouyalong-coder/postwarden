# ADR 0004：构建期 Rust 插件

状态：已确认。

## 决定

MVP 提供可注册和执行的 Rust 插件接口，插件以独立 crate 在构建时链接到 PostWarden。增加或升级插件需要重新构建并发布服务。流程支持提交前、发送前与结果后三类钩子，控制类钩子可修改、拒绝或暂停。插件配置和暂停状态持久化。

后续扩展增加了邮件成形 `compose` 钩子：请求按插件 ID 提供输入，插件在发件身份授权前生成草稿，核心随后进行授权与完整校验。插件还可通过 `manage` 暴露管理员资源；核心统一处理会话与 CSRF。内置 `mail-template` 插件通过这两个接口管理模板并参与发信，可由管理员停用。

## 理由

PostWarden 是开源项目，二次开发者需要在核心发送流程增加模板、审核等特殊处理。构建期插件让扩展代码拥有清晰接口和独立模块，同时保持单服务部署，避免在 MVP 中实现插件包格式、运行时沙箱、热更新及跨版本 ABI。

## 主要备选

- 只预留函数或事件：不足以形成可供二次开发者使用的注册、配置与控制流程机制。
- 可上传 WASM 插件包：支持无需重建的安装，并能限制运行资源，但要同时设计跨语言接口、宿主能力、版本兼容、管理界面扩展和插件包生命周期；留待需求明确时引入。
- 独立插件进程：语言自由度高，但会增加部署、通信和故障处理成本。
- Rust 原生动态库：跨版本二进制兼容和进程隔离难以保证，不作为面向第三方的插件机制。

## 后果

构建期插件是受信任的同进程代码，部署者应审核所加入的插件。核心仍需对插件返回的内容重新校验，发送前插件失败时停止发送，结果通知失败时保留真实 SMTP 结果。暂停任务依赖插件版本和状态，禁用或升级插件必须先处理未完成任务。
